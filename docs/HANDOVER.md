# ShopDock Local v0.3.0 · 交接说明

日期：2026-11-02。基于 v0.2.1 源码增量实现。

## 本版变更

- 所有电商商品、订单、SKU、库存任务切到 Playwright 商家网页，不再调用原电商 Commerce API。
- 六个平台统一商品创建 / 编辑 / 上下架任务，按每店配置的 DOM 规则操作、验证网页回执并保存各店商品 / SKU ID。
- 电商后台与视频账号有独立登录、检查、状态、后台入口。电商支持本地登出；商家 profile 按店铺隔离在 `browser/commerce/`，不使用 MPAU Cookie。
- 电商登录 Cookie / 本地存储由持久浏览器保存。接口、任务参数和日志不返回 Cookie，也不把电商 API 凭据传给浏览器子进程。
- 旧数据增量迁移，关闭旧 API 开关，保留视频状态。网页订单纳入库存扣账、CSV 来源保护与重新核算。
- 提交前检查商品 / 映射 / 规则快照；回执不明不自动重发。库存写前持久占额，逐项读回后释放未知状态。
- 界面移除电商 API 凭据表单，保留独立快手视频凭据，加入六平台批量流程和刷新状态。

## 使用与升级

完整镜像：`docker compose up -d --build`，默认 http://localhost:8080。保持原 Compose 项目名与数据卷。升级前停止旧服务并备份完整数据卷，特别是 `master.key`、数据库与两个 Cookie 目录。严禁删除数据卷。

网页登录后，按 [COMMERCE_BROWSER.md](COMMERCE_BROWSER.md) 配置实际后台页面规则。扫码桌面由队列中的登录任务拉起浏览器，无任务时可以为空白。普通外部后台链接只用于参考，手工浏览器的登录不会自动复制到工作台隔离 profile。

`compose.core.yaml` 没有浏览器，仅用于本地资料和 CSV。Windows `start-local.bat` 默认也需额外安装 Playwright / 浏览器才能执行电商网页任务。

## 尚需真实账号验收

本版没有真实商家账号，未提交真实商品、修改真实库存或发布真实视频。平台入口已配置，但平台登录后的 DOM、类目必填项、商品审核、权限、风控和店铺身份需实店配置与验收。通用页面执行器和模拟页面测试通过不代表六平台商家 UI 都已完成适配。

交付前回归结果见 [VALIDATION.md](VALIDATION.md)。原 v0.2.1 交接保留在工作区根目录同名原文件；旧平台 API 文档已标为历史资料，勿按旧授权步骤操作。
