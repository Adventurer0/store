# ShopDock Local v0.3.7

2026-11-03。发布流程与页面切换修复，无新增依赖或数据库迁移。

## 修复

- 快手专用适配已经填写成功的主图、详情图和业务属性不再被通用填表重复执行，避免追加两份图片。
- 统一发布正确分派 `product_create` / `product_update` 自定义工作流；执行前使用原有工作流校验，合并店铺默认值与商品配置。更新不向工作流传递仓库库存。
- 通用新建商品不使用单独的“保存”按钮，也不把“保存成功”认作审核提交成功；更新仍允许已关联商品的保存回执。
- 点击最终提交前再次核对店铺身份、评分指纹、有效期和实际分数；已经读取到平台评分的草稿不能在提交时通过“评分消失”绕过检查。回执保留本次评分与平台错误码。
- 没有评分功能的平台在未提供评分时保留空证据，不将“未提供评分”误判为“无效评分”；本地预检仍独立要求 ≥95。快手新建仍必须取得实际平台评分 >90。
- 没有适配的类目和 SKU 结构明确报告缺项，避免跳过规格价格后把商品标为已完整回填。
- 审核回查、失败店铺重试的迟到响应不会覆盖新打开的批次或其他页面。
- 静态脚本和样式使用版本标识，HTML / 素材脚本响应要求缓存校验，避免升级后仍加载旧脚本、缺少统一发布与素材仓库菜单。

## 验证

见 [当前验证记录](VALIDATION.md)。自动化商家页面均由本地 HTML 提供，不向真实平台提交商品。

## 使用与边界

进入“商品中心”选择商品，再点“批量发布”，或直接进入“统一发布”。建立批次后读取平台要求，在本地填写公共资料和平台差异项，再回填检查并确认提交。

“素材仓库”支持本地文件 / 目录导入、分类、筛选、直接预览和悬浮放大；被商品或发布草稿引用的素材不能直接删除。

各平台真实商家页面尚未全部完成实店验收。通用提交必须有可识别的入口、完整字段和商品编号回执；未支持的类目、规格结构会阻断。快手更新的 SKU 填写尚未提供内置适配，需要已验证的更新工作流。平台审核通过与提交受理分开记录，不保证自动通过审核。
