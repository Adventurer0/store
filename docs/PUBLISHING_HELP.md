# 登录成功，为什么商品仍显示“待配置”？

电商登录只建立了商家后台的登录会话。发布商品还需要程序知道这个平台的发布页面、必填项目、图片上传入口、SKU 表格、提交按钮以及提交后的商品编号。这些页面操作规则在旧界面中称为“工作流”，是程序的平台适配，不是店铺经营上的审批流程。

如果提示缺少 `commerce_browser.workflows.product_create`，表示旧批量创建仍在等待该店的自定义页面规则；统一发布可以不依赖它：快手使用内置创建适配，抖音 / 微信使用通用内置提交（要求能识别唯一的新增商品入口和提交回执）。反复扫码或开启视频登录不能补齐旧批量规则。

这类适配应由系统提供并随平台页面更新维护，不应要求普通店主手写网页控件规则。当前通用执行器和 Cookie 登录可用，不等于每个平台的实际发布页面已经适配并验收。

## 回到之前的发布批次

“统一发布”页面的“发布记录”列出最近的批次，显示状态、目标店铺数量、已提交数量和最近更新时间。默认显示最近 20 个批次，更早的记录仍保留在本地数据库，不会被页面自动删除。

- “编辑中”“可提交”的批次可以打开后继续填写，也可以删除。删除只清理本机的发布草稿和平台字段填写记录，不会删除本地商品资料，也不会影响平台上已经提交的商品。
- “已提交”“执行中”“结果待核对”的批次保留用于对账，删除按钮不可用；后端也会再次拒绝，避免把提交记录和平台回执一起丢掉。
- 打开某个批次后，地址栏会变成 `#publishing/<批次ID>`。保留书签或把链接发给自己，可以在同一部署的其他浏览器里直接回到该批次；本机 localStorage 只作为没有链接时的兜底。
- 如果链接里的批次已经删除，页面会清除失效记录并回到发布记录列表，不会停在空白页。
- 在“任务队列”里，读取平台要求、回填检查和统一提交三类任务都显示中文名称；带批次信息的任务提供“打开发布批次”，可直接回到当时核对的表单。

## 电商后台登录（v0.3.5）

v0.3.5 起，登录任务打开的是各平台真正的登录页，而不是招商或介绍首页：

| 平台 | 登录入口 | 登录完成后的落点 |
| --- | --- | --- |
| 抖音小店 | `https://fxg.jinritemai.com/login/common` | `/ffa/mshop/...`，多店账号会先到选店铺页 |
| 快手小店 | `https://s.kwaixiaodian.com/`（自动跳转 `login.kwaixiaodian.com`） | `s.kwaixiaodian.com/zone/...` |
| 微信小店 | `https://store.weixin.qq.com/` | 小店后台（`/shop` 或工作台） |
| 淘宝 / 天猫 | `https://myseller.taobao.com/`（自动跳转 `loginmyseller.taobao.com`） | 千牛卖家中心 |
| 京东 | `https://shop.jd.com/`（自动跳转 `passport.shop.jd.com`） | 京东商家后台 |
| 拼多多 | `https://mms.pinduoduo.com/`（自动跳转 `/login/`） | 商家后台首页 |

行为说明：

- 登录页、`login.*` / `passport.*` 域名都不会被当成“已登录”；选店铺页、工作台和商品管理页会被识别为已登录，不再要求页面必须出现某个固定菜单。
- 扫码成功后浏览器会自动关闭，扫码桌面弹窗也会自动关闭；正常等待上限为 5 分钟。
- 如果平台页面停在原处没有跳转，可在扫码窗口点“我已完成登录”。程序会先核对页面确实离开了登录页，再保存会话；仍停留在登录页时会明确拒绝，不会伪报成功。
- “检查电商登录”会打开需要登录的商家页面作为探针：未登录会被重定向到登录页并判定失败；不会因为打开的是招商首页就误判。
- 登录任务超时、浏览器被手动关闭或进程中断时，任务会进入“结果待核对”，并自动释放该店铺的登录锁；可以重新发起，不需要重启容器。

## 使用者需要准备什么

1. 在“店铺连接”分别登录电商后台与视频账号；发布商品使用电商后台登录。
2. 在“商品中心”准备真实商品标题、描述、主图、详情图、价格和 SKU 编码。
3. 核对目标店铺、商品类目、运费模板，以及该类目在商家后台要求的品牌、资质或其他属性。平台要求的材料由商家提供。
4. 首次适配时，在测试商品上检查后台字段与提交回执；规则验证完成后，再从工作台预检并提交。
5. 创建商品与分配库存分开。新建商品先以零库存提交并读回验证，再从“统一库存”分配店铺可售额度。

“待配置”本身不会阻止左侧导航；如果切换页面后任务列表又覆盖回来，是界面刷新问题，应修复刷新与切页竞态。

## 快手用户：填表预览与统一发布

在“商品中心”找到商品，点击“快手填表预览”，选择已登录的快手店铺，核对完整类目、品牌、主要材质、闭合方式和运费模板。默认不上传图片；如果需要程序将商品中心已选择的图片上传到快手，请勾选相应选项，再点击“上传图片并准备表单”。

这条路径使用内置的快手页面适配，不需要填写工作流 JSON。程序会检查店铺身份，尝试准备主图、类目、标题、属性和详情图，并显示已填项目及需要人工补充的项目。点“打开浏览器窗口”查看实际表单。预览最长保留 10 分钟，可以点击“结束预览”提前关闭。**填表预览不点击“提交审核”或“保存草稿”**；平台可能自动暂存填写内容，预览不会保存平台商品 ID。

需要真正提交时，请用“统一发布”建立批次并完成回填检查。必填项、零库存 SKU、店铺身份和平台真实评分均通过且你确认后，程序会：
1. 再次核对 SKU 编码、价格、零库存和平台必填控件；
2. 在点击前重新读取平台评分，必须高于 90 分；
3. 点击“提交审核”，读取明确的成功提示与商品 ID；
4. 打开该商品的只读详情页，按外部 SKU 编码读取平台 SKU ID，并再次核对店铺身份。

没有读到明确回执或商品 ID 时，任务进入“结果待核对”，不会自动重复提交。快手内置提交**只支持新建商品**；已关联平台商品的商品不能重复提交。若店铺已配置有效的 `product_create` 回执工作流，则沿用该自定义工作流。SKU 颜色 / 尺寸等属性仍须与平台当前生成的规格选项一致，无法唯一匹配时会在本地列出，不会按行号猜测。

## 本地质量预评分（≥95）

统一发布在提交前会计算 0–100 的本地分，权重为：类目与属性 20、必填完整性 20、主图 20、详情内容 15、标题与卖点 10、SKU/价格/库存 10、物流与服务 5。**低于 95 分或存在硬性阻断时，提交按钮不会放行。**

硬性阻断包括：未选类目、必填项为空、主图数量不足、本地图片尺寸读不出、快手没有 3:4 主图、标题超限、SKU 编码/价格无效、新建商品 SKU 库存不为零。品牌授权、资质和真实材质不能由程序编造，缺少对应必填项时只会阻断并提示补齐。

平台评分是另一层证据：快手新建商品仍要求平台真实评分高于 90；抖音 / 微信等没有可读取平台评分时，本地 ≥95 即可提交，平台一旦返回评分证据，仍会校验 >90。界面会分别显示本地分和平台分，不会把本地分冒充平台分。

## 新建与更新

新建批次时可选“更新已关联商品”。更新要求所选商品在每个目标店铺都已有平台商品 ID，提交后保持原商品 ID，不生成第二个商品；缺少任一关联会在创建批次时阻断。快手更新使用已知编辑页；其他平台的更新需要在该店 `commerce_browser.edit_url` 中配置包含 `{external_id}` 的 HTTPS 模板，未配置时不会猜测后台地址。

## 失败重试、审核回查与错误码

- “重试失败店铺”只对状态为“待补资料”的目标重新入队；已提交、已成功和待核对的目标不会自动重发。
- “回查审核状态”读取已提交商品的平台页面，归类为审核中、审核通过、审核驳回、已下架或状态未知。读取失败只更新审核回查结果，不改动发布状态。快手使用已知商品详情页；其他平台需配置 `commerce_browser.audit_url`（包含 `{external_id}`）。
- 平台原始错误码会保留并显示；已知关键词会翻译成本地提示，未知错误不会被改写成成功。

## 技术维护人员如何配置

当前高级入口在“店铺连接 → 店铺设置 → 电商后台管理设置 → 后台网页规则与商品默认配置 JSON”。规则放在 `commerce_browser.workflows` 下，每个动作单独适配：`product_create`、`product_update`、`product_list`、`product_delist`、`fetch_skus`、`inventory_sync` 和 `orders`。

必须在实际登录后的页面核对 URL 与控件，不能直接复制示例中的占位选择器。商品创建至少需要：

- 当前商家身份校验，避免同一平台登录到另一家店。
- 标题、类目、运费、图片、类目必填属性及全部 SKU 的填表步骤。
- 每个 SKU 明确写入零库存，提交按钮标记为提交动作。
- 新出现的成功提示，以及平台商品 ID。
- 按外部 SKU 编码读取平台 SKU ID，并逐项读回库存确认为零。

规则结构和支持的控件类型见 [网页规则技术说明](COMMERCE_BROWSER.md)。配置示例只是结构说明，不能证明真实平台已经适配。预检通过也只表示本地配置和登录检查通过，最终还会检查当前后台页面与平台要求。

只读诊断接口为 `GET /api/stores/{store_id}/commerce/readiness`，需要工作台管理员登录。它分别报告登录、浏览器环境及各项页面适配状态，不打开商家浏览器，不提交商品，也不返回 Cookie 或原始页面规则。
