# ShopDock Local v0.3.3 · 发布说明

日期：2026-11-03。基于 v0.3.2 增量实现，保持 FastAPI + SQLite + 商家网页任务模型。

## 本版范围

v0.3.2 之前，即使快手已有内置填表预览，统一发布仍要求每家店配置 `commerce_browser.workflows.product_create` 才能点击审核。本版把已经存在并通过本地 Chrome 用例验证的 `kuaishou_submission` 适配器接入统一发布提交链路，使快手商品可以在不手写工作流的情况下完成“检查 → 提交审核 → 回读商品 ID / SKU ID”。

## 行为变化

### 统一发布提交

- 快手目标店未配置有效 `product_create` 回执工作流时，使用内置提交适配器。
- 已配置有效自定义工作流时继续沿用原流程，不覆盖店铺配置。
- 内置提交只允许新建商品；已有关联平台商品仍阻断，避免重复发品。
- 提交前依次检查：
  1. 当前店铺身份；
  2. SKU 表头、编码、价格、零库存逐行回读；
  3. 平台必填控件与校验错误；
  4. 平台实际评分严格高于 90 分，并在点击前再次读取；
  5. 页面尚不存在成功回执或商品 ID，避免重复点击。
- 点击后读取明确成功提示和商品 ID；随后打开只读商品详情页，按外部 SKU 编码读取平台 SKU ID，并在详情页再次核对店铺身份。
- 未读到明确回执或商品 ID 时返回“结果待核对”，不自动重试。
- 快手商品提交成功后写入平台商品 ID 与 SKU 映射，并标记为该视频账号自建商品，后续视频挂小黄车可直接使用，不需要再手工补标记。

### 失败分类与诊断

- `submit_workbench` 子进程超时或输出无法解析时归类为“结果待核对”，不再误判为可安全重试的“待配置”。
- 快手创建适配的评分接受整数或小数（例如 `97`、`97.0`、`97.5`），仍要求严格大于 90 且不超过 100，并拒绝布尔值和 `NaN`。
- 店铺接入检查在缺少快手创建工作流时提示“统一发布可使用内置快手创建路径”，同时保留旧批量任务仍需页面规则的事实。
- 平台能力表区分快手“统一发布内置创建”与其他平台的页面规则要求。

### 兼容性

- 不新增数据库表或列，不需要数据迁移。
- 接口字段未变；仅店铺接入检查的说明文案增加内置适配提示。
- 快手填表预览行为不变：仍然只填表，不点击提交或保存草稿。
- 其他平台的统一发布仍需有效回执工作流；未适配时继续阻断。

## 验证

在 Windows 宿主、`shopdock:local` 完整镜像内执行，挂载新版源码并使用临时 `APP_DATA`，未连接真实店铺：

- 完整 pytest：**253 passed**（新增 5 项：内置提交端到端、非快手回退、超时分类、浮点评分、接入检查文案）。
- jsdom 界面流程：**25 passed**。
- `node --check`：app.js / library.js / publishing.js 通过。
- 新增真实 Chrome 用例：不配置任何 `product_create` 工作流，通过 `commerce_forms.run` 完成 SKU 填写、评分复查、提交、商品 ID 与 SKU ID 回读；没有额外页面残留。
- 新增超时用例：`submit_workbench` 超时为 `Uncertain`，`prepare_workbench` 超时为 `Blocked`。

## 未验收范围

仍没有真实快手商家账号。内置适配基于已观察到的 Nexus 页面结构和本地模拟 HTML，真实类目、属性、资质、风控、图片审核、平台评分展示与提交回执仍需实店验收。若真实页面表头、合并单元格、必填控件或回执结构变化，适配器会阻断或进入待核对，不会猜测填写。
