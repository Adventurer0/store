# ShopDock Local v0.3.2 · 发布说明

日期：2026-11-03。基于 v0.3.1 源码增量实现，保持现有分层、网页任务模型与失败即停策略。

## 本版范围

v0.3.1 已能建立统一发布批次、读取平台要求、回填并检查评分，但页面只记得“最后一个批次”：换浏览器、清缓存或关掉页面后，未提交的草稿没有入口；任务队列里的发布任务也只显示内部名称。本版补齐批次的生命周期与任务联动，不改变平台适配边界。

## 变更

### 后端

- `GET /api/publish-groups` 支持 `limit`（1–50，默认 20）与 `offset`，返回 `total`。每个批次附带 `status`、`store_count`、`target_count`、`submitted_count`、`uncertain_count`、`updated` 和草稿摘要。原来只有 `product_count` / `product_titles` 的调用方不受影响。
- 列表不再按草稿逐条查询标题：计数、批次、草稿、目标与任务状态各一次查询，批次多时不会出现 N+1。
- 新增 `DELETE /api/publish-groups/{id}`：在单个事务中删除未提交批次的全部草稿与目标记录。存在已提交、执行中或待核对目标，或仍有排队 / 执行中 / 待核对任务时，返回 409 并保留记录；本地商品资料不受影响。
- 统一发布任务写入 `payload.group_id`，任务队列可据此回到原批次。旧任务没有该字段时只少一个入口，不影响执行。
- 记录列表复用详情页的中断任务判定：`queued_*` 目标若对应任务已中断、失败或待核对，不再永久显示“执行中”。

### 前端

- “统一发布”新增“发布记录”：列出最近批次的状态、店铺与项目数、最近更新时间，可打开未提交批次继续填写，也可删除未提交批次。
- 打开批次后地址栏变为 `#publishing/<批次ID>`；刷新、收藏或在同一部署的其他浏览器打开都能回到该批次。链接中的批次已删除时，清除失效的本地记录并回到列表。
- 删除需要二次确认；已提交、执行中、待核对的批次按钮不可用，后端仍会再次校验。
- 任务队列为 `workbench_collect` / `workbench_prepare` / `workbench_submit` 显示中文名称，带批次信息的任务提供“打开发布批次”。

### 兼容性

- 不新增数据库表或列，不需要数据迁移。
- `GET /api/publish-groups` 原有字段保留；新增字段为追加。
- 深链只是更明确的定位方式，没有链接时仍回退到本机上次打开的批次。

## 验证

在 Windows 宿主、现有 `shopdock:local` 完整镜像内执行，挂载新版源码并使用临时 `APP_DATA`，未连接真实店铺：

- 完整 pytest：**248 passed**，耗时约 90 秒；仅有既有 FastAPI/Starlette 的 httpx 弃用提醒。
- `node --check app/static/app.js`、`node --check app/static/publishing.js`：通过。
- jsdom 界面流程：**25 passed**，包含发布记录、深链回退、删除二次确认、任务批次入口，以及原有导航与素材仓库用例。
- `docker compose config --quiet`（完整 / 核心）：通过。

新增后端用例覆盖：批次状态汇总、任务 `group_id`、原子删除、活动任务与已提交回执保护、分页边界、损坏的批次记录、中断任务不误报“执行中”、路由 CSRF 与 404。

## 未验收范围

仍没有真实商家账号。批次记录只管理本地草稿，不代表平台商品已经创建或更新；六个平台的真实 DOM、类目必填项、权限、风控、提交回执与库存语义仍需实店配置和验收。统一发布的最终提交仍要求平台适配返回可核对的商品 ID 与评分，未适配时保持阻断。
