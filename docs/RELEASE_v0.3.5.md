# ShopDock Local v0.3.5 · 电商登录闭环修复

日期：2026-11-03。基于 v0.3.4 增量修复，无数据库迁移。

## 修复的问题

### 1. 抖音打开的不是登录页

旧实现统一打开平台门户 `https://fxg.jinritemai.com/`。该地址现在会落到招商介绍页
`/ffa/mshop/homepage/index?channel=zhaoshang`，没有二维码，用户必须自己找到登录入口。

本版为每个平台增加独立登录地址，抖音改为 `https://fxg.jinritemai.com/login/common`。
门户地址仍只用于域名校验和商家后台入口说明。

### 2. 登录成功后浏览器与扫码窗口不关闭

原因有三点：

- 登录判定只认“商品管理 / 订单管理”等固定菜单文字。抖音多店账号登录后先进入选店铺页，没有这些菜单，判定永远为否。
- 登录等待上限 600 秒，期间浏览器一直保持打开，任务一直显示“正在执行”。
- 前端扫码窗口只是静态 iframe，任务完成后不会关闭。

本版改为：

- 登录页 / 登录域名优先判定为“未登录”；`/ffa/`、`/zone/`、`/shop` 等商家工作区路径和选店铺页可直接判定为已登录。
- 平台仍在显示“手机登录 / 扫码登录 / 密码登录”等强登录文案时，不会被误判。
- 登录成功后立即关闭浏览器；正常等待上限降为 300 秒；扫码窗口轮询任务状态，成功或失败都会自动关闭并刷新店铺卡片。
- 新增“我已完成登录”：平台不自动跳转时，用户可主动结束；程序先核对页面已离开登录页，仍停留在登录页则拒绝。

### 3. 卡住的登录任务长期占住店铺

旧逻辑中，浏览器崩溃或任务中断后，`running` 记录会一直保留，之后所有登录操作都会提示
“当前账号任务正在排队或执行”。

本版增加任务看门狗：`commerce_login` / `account_login` / `commerce_prepare_product`
和普通长任务分别有固定上限，超过后标记为“结果待核对”，释放登录锁。错误提示也会说明
正在执行的是“登录电商后台”还是“检查电商登录”。

### 4. 其他平台登录失败

- 快手、淘宝 / 天猫、京东、拼多多的门户会自动跳转登录域名，本版把 `login.*`、
  `passport.*`、`loginmyseller.*` 统一识别为登录页。
- “检查电商登录”改为打开需要登录的商家页面作为探针；未登录必然被重定向，避免把招商页
  或门户首页误判成已登录。
- 微信小店登录页与后台同域，使用登录文案 + 工作区路径 + Cookie 组合判定。

### 5. 自动订单同步重复堆积

缺少 `commerce_browser.workflows.orders` 的店铺不再每分钟创建一个阻断的订单同步任务；
接入检查仍会报告缺失的适配。

## 涉及文件

- `app/commerce_profiles.py`：登录地址、探针地址、登录页/工作区判定。
- `app/commerce_worker.py`：登录状态机、300 秒上限、手动确认、关闭窗口容错。
- `app/commerce_browser.py`：登录超时、`confirm_login` 标记。
- `app/jobs.py`：任务看门狗、登录占用提示、自动订单同步前置检查。
- `app/main.py`：`POST /api/stores/{sid}/commerce/login/confirm`。
- `app/connectors.py`：向界面暴露 `login_portal`。
- `app/static/app.js`：扫码窗口自动关闭、手动确认、登录入口链接。
- `tests/test_commerce_login.py`（新增）、`tests/test_commerce_api.py`、`tests/test_ui.cjs`。
- `README.md`、`docs/PUBLISHING_HELP.md`、`docs/HANDOVER_v0.3.5.md`。

## 验证

- 完整 pytest：**284 passed**。
- jsdom 界面测试：**27 passed**（新增扫码窗口自动关闭用例）。
- 真实 Chrome 用例：抖音 `/login/common` 请求、登录后进入选店铺页、Cookie 写入、
  `session.json` 生成、点击“我已完成登录”但仍在登录页时拒绝。
- 临时实例上以真实地址验证了六个平台匿名访问的最终 URL 与登录页文案。
- 临时数据卷的真实界面验收：点击“登录电商后台”后，扫码桌面显示
  `fxg.jinritemai.com/login/common` 的手机登录页；点“我已完成登录”后任务明确
  失败为“页面仍停留在登录页”，扫码弹窗自动关闭，Chrome 子进程全部退出，页面无脚本错误。

## 边界

- 尚未用真实商家账号完成扫码验收；平台可能调整登录页结构、风控或验证码流程。
- 微信小店后台的登录文案与工作区路径需在真实账号下再确认一次。
- 登录成功后只证明会话可用，不代表商品创建 / 更新 / 订单页面适配已经完成。
- 本版不引入新的第三方依赖，不改数据库结构。
