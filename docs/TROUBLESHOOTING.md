# 故障排查

v0.3.0 网页管理：电商与视频需要分别登录；电商过期请重新点“电商网页登录”。缺 `commerce_browser.workflows` 表示需要按实际后台配置页面规则，见 [网页规则](COMMERCE_BROWSER.md)。核心镜像没有 Chrome，网页电商请使用默认完整镜像。以下旧电商 API 错误仅供历史版本排查。

## 镜像构建失败

先看失败阶段：基础镜像拉取、pip 下载、GitHub clone、Chromium 下载不是同一类问题。构建主机必须能访问对应来源。不要向网上未知服务上传店铺 Cookie。可先使用 `compose.core.yaml` 验证本地业务面板，再处理完整镜像依赖。

MPAU 固定提交写在 Dockerfile 的 `MPAU_REF` 中。修改版本后应重新验证各平台 CLI，不能假设上游接口永远不变。

## 网页打不开

检查 Docker 服务与容器日志：

```bash
docker compose ps
docker compose logs --tail=100 shopdock
```

确认 8080 端口没有被其他程序占用。改端口时使用 `.env` 的 PORT，再 `docker compose up -d`。在其他设备打开 localhost 指向的是该设备自身，需要改为部署电脑的局域网 IP，并同步修改 BIND_ADDRESS 和 ALLOWED_HOSTS。

出现 `Invalid host header`：把实际访问的域名 / IP 添加进 ALLOWED_HOSTS。仅凭据有效还不够，访问域名也需要匹配。HTTPS 反向代理请正确转发 Host / WebSocket。

## 500 / 数据卷权限错误

默认 named volume 会自动初始化。若改成主机目录挂载，请让 UID 10001 可以读写目录。不要混用两个同时工作的容器指向同一个数据目录。本版只允许一个 worker，不能用 `--workers 4` 扩容。

丢失 master.key：恢复原始密钥与数据库备份；不要删库 / 自动换新密钥。凭据不回显是正常行为，留空保存会保留已有值。

## 扫码窗口黑屏或未出现二维码

1. 必须运行完整镜像，核心镜像不含桌面。
2. 先在店铺卡片点击“扫码登录”，再打开扫码窗口。仅打开桌面不会自动登录某个平台。
3. 队列串行，前面如果有长视频上传，需等其完成。
4. 检查任务日志、容器日志；桌面日志在 `/data/logs/vnc.log` 与 `xvfb.log`。
5. 在窗口里手动完成手机扫码 / 验证。不要刷新导致重复创建登录任务。

桌面 VNC 端口仅绑定容器回环地址；所有浏览器访问均由 Web 面板登录校验。不要另外暴露一个无鉴权的 noVNC / VNC 端口。

## 为什么有“待配置”

未启用 API、凭据缺失、模板未填写、目标操作未实现、商品 ID 未关联、视频会话未经验证、平台不支持挂商品，都会导致本地阻止执行。点任务详情查看原因。修正后重新预检，涉及请求内容的旧任务可先取消。

## “已提交”和“已完成”不同

商品 API 成功可能只是创建草稿 / 提交审核，视频 CLI 退出 0 也不等于审核已通过。因此任务先记为“已提交”，你核对平台后选择实际结论。看不见作品或挂链失败时不要直接标记成功。

出现“结果待核对”意味着超时、中断或返回格式无法识别，可能已经发生外部写入。程序不会自动重试。先核对平台，确认未成功才重试，或者保存“未发布成功”的核对结论后用新参数创建任务。

## 商品发布被拒绝

查看平台业务错误。常见原因是权限、Token 过期、类目未获准、运费 / SKU 模板、品牌资质或图片地址不符。不要仅重复点击重试。类目 / 资质资料须与本店匹配。

本地更新价格与库存不会自动联动其他店铺。订单同步也不会自动减库存，避免在未校准 SKU 映射和库存策略时误扣。

## 订单同步不完整

每次只查选定更新时间范围，最多 7 天。平台对历史窗口、限流和字段权限另有限制。微信需逐单读取详情，订单多时耗时较长。最多抓取 500 页，遇到游标不推进 / 返回结构变化会明确失败，已写入的订单保留；缩小范围后重新同步会按店铺和订单号去重。

CSV 金额必须是整数分，同一文件内的同店订单号不能重复。订单已通过 API 获取时，CSV 不覆盖其状态。

## 开发预览与验证限制

此包生成时，API 和业务测试在 Python 3.12 环境通过；浏览器预览服务与主执行环境不共享 Python 依赖，未完成浏览器实测。交付环境没有 Docker 引擎，因此不包含已构建镜像，也没有声称容器构建和真实店铺发布已经通过。目标设备的运行日志是下一步排障依据。
