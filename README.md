# ShopDock Local · v0.3.7

本版修复快手图片重复上传、统一发布的自定义工作流分派、保存草稿误判发布成功、提交前评分变化和迟到的审核回查 / 重试响应覆盖其他批次等问题。没有适配的类目和 SKU 控件会明确报告缺项，不再跳过后直接提交。详细范围见 [v0.3.7 修复说明](docs/RELEASE_v0.3.7.md)，用法见 [发布帮助](docs/PUBLISHING_HELP.md)。

本地多店工作台：一份商品资料，在抖音、快手、微信小店、淘宝 / 天猫、京东和拼多多之间管理商品、订单与库存。

本版电商任务全部通过商家网页执行，复用每家店独立的浏览器 Cookie / 本地存储。旧电商 API 开关被停用；无需填写 App Key 或电商 Access Token。视频账号继续单独登录，快手官方视频授权也单独保存。

**验收边界：统一任务流程、会话隔离、数据迁移、库存保护、质量检查、登录、提交回执和本地界面有自动测试；尚未完成六个平台的真实商家发布验收。快手新建提供内置适配；其他平台须具备已识别的入口、类目、SKU 控件和商品编号回执，缺失时明确阻断。快手更新 SKU 及其他未支持的编辑、上下架、订单、库存页面，仍需适配并验证 DOM 规则。不能视为六个平台开箱即用。**

## 启动

安装并启动 Docker Desktop，解压后双击 `start-windows.bat`，或执行：

```bash
docker compose up -d --build
```

打开 http://localhost:8080，创建管理员（密码至少 12 位，无默认密码）。完整镜像包含 Chrome、Playwright、视频引擎和扫码桌面。首次构建需要联网。

`compose.core.yaml` 只提供本地商品资料、CSV 和队列；没有浏览器，无法网页登录或执行网页电商任务。不要与完整镜像同时运行。

## 使用流程

1. 在“店铺连接”添加平台和店铺。每家店分别显示“电商后台”和“视频账号”状态。
2. 点击“电商网页登录”，在扫码桌面中登录正确的商家账号。短信、扫码及平台验证由本人完成。登录检查通过后，在本店独立浏览器目录保存会话。
3. 配置该店后台的页面规则及商家身份校验。详见 [网页规则](docs/COMMERCE_BROWSER.md)。可用商品标题、描述、图片、SKU、店铺类目 / 运费配置等变量；只执行点击、填表和上传，不调用商家 API。
4. 在“商品中心”填写公共资料，再通过“多店铺货”或批量管理选择目标店铺，预检并确认任务。每店单独保存平台商品 ID / SKU ID；缺少成功回执或商品 ID 时进入待核对，不会伪报成功。需要逐店读取实际必填项时，用“统一发布”建立批次；关闭页面或换设备后可在“发布记录”回到未提交草稿，已提交或待核对的批次保留用于对账，不能删除。新建批次可选择“更新已关联商品”，只对已有平台商品 ID 的店铺提交更新，不会生成第二个商品。快手目标店在未配置有效创建工作流时使用内置适配；抖音 / 微信使用通用内置提交。失败店铺可单独重试，已成功或待核对的目标不会被自动重发；已提交商品可回查审核状态。
5. 新建商品的映射库存为 0；更新内容时不提供库存变量。网页规则须正确绑定这些变量，并核对平台默认库存。库存由“统一库存”分配店铺额度后独立校准，逐个 SKU 读回确认；结果未知继续占用额度。
6. 订单可手动同步或按店铺开启每 60 秒自动同步。网页规则须覆盖明细和翻页；读取失败不推进成功游标。网页订单按店铺、订单号、SKU 幂等扣账；CSV 仅汇总。
7. 需要视频时，另点“视频扫码登录”和“视频登录检查”。视频登录不会验证电商会话，电商 Cookie 不会交给视频引擎。

电商会话过期后重新登录电商后台；退出电商登录只清除本店本地商家会话。若需要在平台撤销远端会话，另在平台账号安全设置中操作。

## 数据与升级

数据保存在原 `shopdock_shopdock-data` 卷：数据库、媒体、`master.key`、视频 Cookie，以及新增的 `browser/commerce/<store-id>/` 商家浏览器目录。商家 profile 与视频 `mpau/cookies/` 完全分开。浏览器目录包含登录凭据，请按账号密钥保护，不要放进源码包或版本库。

升级前停止旧服务并备份完整数据卷，保持 Compose 项目名与卷不变，再用新源码构建启动。增量迁移保留商品、订单、库存及视频登录状态，电商状态初始为未验证；旧电商 API 凭据保留在加密存储中用于回退，不再驱动任务。旧 API 商品任务缺少网页预检快照会阻断，应取消后重新预检。**不要使用 `docker compose down -v`。** 回退须恢复对应版本备份。

## 库存与任务

同一订单重复同步不重复扣库。取消 / 退款不自动补回实物，验收入库后用“出入库”注明原因调整。已减少但远端未确认的额度不能挪给其他店。离线超过 7 天须分段补拉订单，再恢复自动同步。轮询和串行任务存在延迟，没有跨平台强事务或秒级防超卖保证。

网页提交超时、程序中断、回执不明均进入待核对。核对正确店铺后台后才可确认或重试。后台布局、商品类目、子账号权限或平台验证变化需要更新页面规则；程序不绕过验证码。没有自动发货、自动退款或物流面单。

快手视频挂商品仍使用独立的 `video_app_id` / `video_access_token`，仅用于视频上传发布，且只支持该视频账号自建商品。其他视频使用原 MPAU 通道。详见 [发布帮助](docs/PUBLISHING_HELP.md)、[v0.3.6 修复说明](docs/RELEASE_v0.3.6.md)、[v0.3.5 交接文档](docs/HANDOVER_v0.3.5.md)、[v0.3.4 发布说明](docs/RELEASE_v0.3.4.md)、[v0.3.3 发布说明](docs/RELEASE_v0.3.3.md)、[v0.3.2 发布说明](docs/RELEASE_v0.3.2.md)、[v0.3.0 交接](docs/HANDOVER.md) 与 [验证记录](docs/VALIDATION.md)。

## 开发与验证

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
npm ci
npm run check
npm run test:ui
```

普通测试不访问真实商家。真实 Chrome 的本地 HTML 用例需要 Playwright / Chrome；普通环境自动跳过缺少依赖的浏览器用例，完整测试命令见验证记录。Windows 本地启动 `start-local.bat` 可预览界面；网页管理需额外安装 Playwright 和浏览器，见网页规则文档。
